## 数据与展示合同

机器可读定义以 `schemas/decision-output-v0.1.schema.json` 为准，固定输入以 `prototype/fixtures/decision-demo.json` 为准。根记录、场景和每个证券候选都须明确合成属性。演示证券使用 `DEMO-` 或 `SYN-` 等虚构标识，不能映射为真实证券代码。

| 信息 | 语义与展示要求 |
| --- | --- |
| 快照与系统状态 | 固定合成快照时间、版本与数据性质；不伪装为实时更新 |
| 市场姿态 | 从固定场景选择；不是根据行情计算或推断 |
| 候选行动 | 观察、等待触发、审阅、持有、减仓、退出或不交易的演示状态 |
| 条件与时间 | 明确触发／等待条件、最早可执行时间；未知值用 null 并给出原因 |
| 参考价格 | 仅示意或未知，不能使用真实证券价格或形成可执行建议 |
| 风险门与最大候选仓位 | 原型不授权新增风险；最终风险数值和仓位上限未批准，必须为 null 并说明原因 |
| 失效与退出 | 描述假说失效、退出可行性及执行约束；不把止损当损失保证 |
| 支持与反证 | 证据等级、最强支持和最强反证明确可见 |
| 残余风险 | 首屏展示执行残余风险和退出可行性，不隐藏到审计层 |
| 利润与右尾 | 仅展示研究／待验证状态，不填最终数值目标 |
| 来源与验证 | 合成来源、版本、时间链、验证状态、未知历史样本与归因限制可追溯 |

首屏默认最多三个候选。夹具可包含更多候选以覆盖边界状态，但每个场景最多引用三个；切换场景只切换固定输入，不生成新判断。

第一层展示行动及风险摘要；第二层展开支持、反证、替代解释、资金代理、时间链、业务暴露和执行监控；第三层展示版本、来源、验证与失效记录。最强反证不需要进入最深审计层才能看到。

## 状态语义

状态应分别表达市场姿态、候选行动和阻断原因，不把它们混为同一交易许可。夹具覆盖：

- `SELECTIVE`：选择性研究，不等于允许新增风险。
- `NO_NEW_RISK`：不新增风险；已有持仓的合法降险仍受可卖、权限、流动性和执行约束。
- `INSUFFICIENT_EVIDENCE`：证据不足，明确未知原因，不补造数值。
- `CONFOUNDED`：多个事件或解释重叠，不能可靠归因。
- `WINDOW_CLOSED`：成本后的窗口已经关闭，不因逻辑仍成立而假定可执行。
- `NON_EXECUTABLE`：价格、流动性或退出条件不满足。
- `HOLD`、`REDUCE`、`EXIT`：固定的持有／降险／退出演示，均不构成真实订单或成交保证。

未知字段使用可识别状态、`value: null` 与非空原因。最终风险授权未批准和一般信息未知应有可区分的原因，均不能渲染成零、空白或默认建议。原型中所有新增风险许可保持关闭；合法降险许可不代表实际可成交。
