# Roadmap

## Phase 0：项目规范和工程骨架

- 输入：项目目标、风险原则、技术栈、目录规划。
- 输出：README、项目章程、架构、路线图、风险原则、数据政策、完成定义、AGENTS 规则。
- 依赖：空仓库或现有仓库检查结果。
- 验收标准：文档完整说明目标、非目标、风险声明、第一版限制和建议目录结构。
- 测试要求：检查文件存在、Markdown 可读、无真实交易逻辑。
- 风险点：过早实现业务代码，忽略风险约束。
- 完成定义：规划文档合并，后续任务有明确执行规则。

## Phase 1：软件工程基础

- 输入：Phase 0 文档、Python 3.11、uv、质量工具和工程规范。
- 输出：`pyproject.toml`、CI、pre-commit、ruff、pytest、mypy、Docker、统一配置、统一日志、统一异常处理和基础测试。
- 依赖：Phase 0；无需任何数据源 Token。
- 验收标准：新用户可以执行 `uv sync --all-groups`、`uv run pytest`、`uv run ruff check .`、`uv run mypy`；push 后 CI 自动运行 ruff、pytest、mypy。
- 测试要求：配置读取、日志初始化、统一异常继承关系必须有单元测试。
- 风险点：过早接入数据或策略、配置硬编码、环境变量读取分散、CI 与本地行为不一致。
- 完成定义：工程基础可在本地和 CI 复现，且不包含策略、数据下载、券商连接、API 接入或 Dashboard。

## Phase 2：数据接入和数据质量

- 输入：Tushare/AkShare 数据规范、API 授权、字段说明、Phase 1 工程基础。
- 输出：数据源适配器、元数据记录、质量检查、DuckDB 原型表。
- 依赖：Phase 1；合法 API Token 管理方案。
- 验收标准：记录来源、字段含义、更新时间、授权限制；可重复拉取小样本数据。
- 测试要求：单元测试字段映射；集成测试数据拉取、入库和质量检查。
- 风险点：数据授权不清、字段口径变化、缺失停复牌或复权信息。
- 完成定义：数据血缘和质量报告可复现。

## Phase 3：股票池和交易日历

- 输入：上市公司列表、交易日历、指数成分、ST/退市/停复牌状态。
- 输出：可按时间点复原的股票池和交易日历服务。
- 依赖：Phase 2 数据质量。
- 验收标准：任意交易日能生成当时可知股票池，避免幸存者偏差。
- 测试要求：固定日期股票池回归测试；停牌、涨跌停、ST、退市过滤测试。
- 风险点：使用未来成分股、忽略新股上市期、退市样本丢失。
- 完成定义：股票池有时间语义、状态标签和审计记录。

## Phase 4：因子与信号引擎

- 输入：行情、财务、估值、技术指标、股票池和交易日历。
- 输出：因子计算、因子元数据、信号生成和信号解释。
- 依赖：Phase 2、Phase 3。
- 验收标准：因子只使用信号生成时已知数据；信号包含解释和失效条件。
- 测试要求：因子计算单元测试；时间对齐和未来函数防护测试。
- 风险点：财报发布日期处理错误、参数过拟合、缺乏解释性。
- 完成定义：至少一个研究因子链路通过小样本验证。

## Phase 5：回测引擎

- 输入：信号、股票池、交易日历、价格、费用、滑点和撮合假设。
- 输出：可复现回测结果、交易明细、持仓明细、绩效指标。
- 依赖：Phase 2-4。
- 验收标准：显式支持 T+1、停牌、涨跌停、交易费用和最早可成交时间。
- 测试要求：撮合规则、成本、复权、不可成交场景单元和回归测试。
- 风险点：未来成交价、忽略不可成交、费用低估。
- 完成定义：固定小样本回测结果稳定可复现。

## Phase 6：风险和仓位管理

- 输入：策略信号、组合状态、风险预算、流动性约束。
- 输出：仓位建议、止损止盈、失效条件、风险暴露报告。
- 依赖：Phase 5。
- 验收标准：仓位建议有约束依据，不因单一信号过度集中。
- 测试要求：最大仓位、行业/个股集中度、流动性、回撤约束测试。
- 风险点：极端行情失效、流动性冲击、止损不可成交。
- 完成定义：风险规则可配置、可测试、可解释。

## Phase 7：策略组合

- 输入：多个策略或信号、风险模型、基准指数。
- 输出：组合策略、权重分配、冲突处理和策略归因。
- 依赖：Phase 4-6。
- 验收标准：组合相对基准和单策略有可解释改进或明确取舍。
- 测试要求：策略权重、冲突信号、归因和回归测试。
- 风险点：策略高度相关、过度拟合组合权重。
- 完成定义：组合逻辑有样本外和滚动验证结果。

## Phase 8：每日选股报告

- 输入：最新可用数据、信号、风控、组合建议。
- 输出：每日候选股票报告、风险提示、信号解释和可成交时间说明。
- 依赖：Phase 2-7。
- 验收标准：报告不构成投资建议，不保证收益，包含失效和风险条件。
- 测试要求：报告格式、字段完整性、免责声明和时间语义测试。
- 风险点：用户误解为确定性买卖建议、数据未更新。
- 完成定义：报告可重复生成并保留历史版本。

## Phase 9：Dashboard

- 输入：报告、回测结果、实验记录和风险指标。
- 输出：可视化查询和研究看板。
- 依赖：Phase 8。
- 验收标准：展示清楚数据日期、信号时间、风险提示和实验版本。
- 测试要求：API/页面基础测试、关键图表数据一致性测试。
- 风险点：展示误导、缺少版本说明。
- 完成定义：Dashboard 仅展示研究信息，不执行交易。

## Phase 10：模拟盘

- 输入：每日信号、模拟账户、模拟撮合规则。
- 输出：模拟订单、模拟成交、模拟持仓和模拟绩效。
- 依赖：Phase 5-9。
- 验收标准：明确模拟属性，不连接真实券商，不执行真实订单。
- 测试要求：模拟撮合、T+1、费用和不可成交测试。
- 风险点：模拟结果被误认为实盘能力。
- 完成定义：模拟盘记录完整且可审计。

## Phase 11：监控和持续优化

- 输入：数据质量指标、任务日志、报告生成状态、模拟盘表现。
- 输出：监控告警、漂移检测、策略复盘和优化计划。
- 依赖：Phase 2-10。
- 验收标准：关键数据失败、异常指标和报告延迟可告警。
- 测试要求：监控规则、告警路由、异常数据回归测试。
- 风险点：静默失败、策略漂移、过度频繁调参。
- 完成定义：形成稳定复盘与迭代机制。
